# 上游更新維護

本專案追蹤 `Alos21750/UAV-Downloader` 的 `master` 已提交更新，定期與 `CloudWorkTools/UAV-Downloader` 的主分支比較。上游的 PR 不作為更新依據。

## 定期差異報告

[追蹤上游更新](../.github/workflows/sync-upstream.yml)每天於臺灣時間 09:17、21:17 執行，也可在 Actions 手動啟動。報告由 [compare_upstream.py](../scripts/compare_upstream.py)產生，包含：

- 雙方版本與共同基準。
- 上游尚未納入、本專案自行維護的提交數與最近 20 筆提交。
- 雙方各自相對共同基準的檔案差異，依 Web／UI、NAS／背景服務、下載核心、桌面語系、測試及封裝等模組分類。
- 合併衝突檔案與處理建議。

每次執行都將完整報告寫入 Actions 摘要，並更新同一個「[追蹤] 上游版本與本專案差異」Issue。Issue 顯示最新結果，歷次執行的摘要則保留各次比較。沒有更新時也會明確回報。

排程只讀取 Git 提交，使用 `git merge-tree` 評估衝突；不切換到上游版本，也不執行上游程式。GitHub 內建權杖只有程式碼讀取與 Issue 寫入權限，不會建立同步 PR 或合併更新。

## 處理建議

| 比較結果 | 建議 |
| --- | --- |
| 上游提交均已納入 | 無需同步 |
| 僅有文件或圖表更新 | 暫緩同步，避免為非功能更新牽動本專案 |
| 有功能或建置更新，且有衝突 | 先人工整合衝突，再執行相容性檢查 |
| 有功能或建置更新，且無文字衝突 | 可進入整合評估，通過相容性檢查後再決定是否合併 |

分類依檔案範圍產生，不是對程式語意的完整分析。沒有文字衝突不代表功能一定相容，也不會單憑提交標題判斷可合併。

維護者須確認 Web／UI、NAS 擴充與下載核心的公開介面仍保留，再執行 [Web 與 UI 相容性檢查](../.github/workflows/web-check.yml)。該檢查包含 NAS、設定、佇列、核心儲存行為、批次選取與容器建置啟動。實際站點與個別 NAS 仍需抽查。

## 執行與停用

Fork 必須啟用 Actions 及 Issues。排程可能因 GitHub 負載而延遲，實際比較版本與時間以報告為準。

需要停止追蹤時，可在 Actions 停用「追蹤上游更新」工作流程，追蹤 Issue 和既有執行紀錄均保留。原有 Windows 發行、CLI 映像及星數圖表工作流程在本組織預設不隨推送自動執行，仍可由維護者手動啟動。
