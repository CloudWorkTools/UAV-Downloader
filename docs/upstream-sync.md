# 上游更新維護

本專案以同步 PR 評估原作者更新，保留維護者對合併的決定權。下載核心的來源為 `Alos21750/UAV-Downloader`，Web／UI 與 NAS 擴充由 `CloudWorkTools/UAV-Downloader` 維護。

## 排程與檢查

[追蹤上游更新](../.github/workflows/sync-upstream.yml)每 12 小時檢查一次上游 `master`，也可在 Actions 手動執行。有未納入的提交時，工作流程會建立 `sync/upstream-` 開頭的分支及 PR；同一提交已有開啟的 PR 時會沿用，再重新啟動相容性檢查。

[Web 與 UI 相容性檢查](../.github/workflows/web-check.yml)從主分支的工作流程定義啟動，將候選提交與目前主分支合併後執行測試。合併衝突、測試失敗、容器建置失敗或服務無法啟動，都會讓檢查失敗。結果會標示在候選提交的 `Web / UI compatibility` 檢查。

建立 PR 的工作只操作 Git 與 GitHub API，不執行上游程式。測試工作只有讀取權限；回報檢查結果的工作不取出或執行候選程式。此流程使用 GitHub 內建權杖，不需另外保存個人存取權杖。

## 合併判斷

維護者在 PR 確認以下項目後，才決定是否合併：

1. `Web / UI compatibility` 成功，且測試涵蓋目前主分支與候選提交的組合。
2. `uav-web/`、`daemon/` 與工作流程的變更沒有移除本專案擴充。
3. 下載核心的公開方法、檔案命名與錯誤行為仍符合佇列銜接方式。
4. 瀏覽、搜尋、全選、加入佇列、設定保存及 NAS 傳送完成必要抽查。

測試通過無法保證所有網站版面與 NAS 裝置都相容；無法確認時應保留 PR，先補回歸測試。此排程不會自動合併，也不會直接更新主分支。

## 失敗處理

有合併衝突時，維護者須在同步分支解決衝突，重新執行 PR 檢查；請保留下載核心與擴充之間的模組邊界。主分支有新提交時，可重新執行追蹤工作流程，讓候選版本與最新主分支重新評估。

若 GitHub 阻止建立 PR，請由組織管理員檢查 Actions 的「Allow GitHub Actions to create and approve pull requests」政策。Fork 的排程也必須先啟用 Actions。上游已納入主分支時，排程只會回報無需同步。

需要停止追蹤時，可在 Actions 停用「追蹤上游更新」工作流程；既有 PR 和主分支內容均保留。原有 Windows 發行、CLI 映像及星數圖表工作流程在本組織預設不隨推送自動執行，仍可由維護者手動啟動。
