# 交付追蹤、部署保護與完整介面驗收 Implementation Plan

> **For agentic workers:** Use subagent-driven-development or executing-plans to implement each task and verify its result.

**Goal:** 落實本次回顧已接受的第 1、2、3 項，避免原型漏接正式功能，讓安全部署及完整手機驗收可重複執行。

**Architecture:** 沿用既有部署工具與共用 CI 入口。將任務保護、相同提交 CI 核對及線上資產驗證收進受版本控制的工具；以正式容器執行完整頁面瀏覽器驗收，保留原有快速測試。

**Tech Stack:** Python、pytest、Node.js CDP、Docker、GitHub Actions。

**Spec:** 使用者於本次回顧接受的第 1、2、3 項；交付狀態以 `docs/delivery-status.md` 記錄。

## Task 1：交付紀錄

- [ ] 建立逐需求的原型、實作、CI、部署證據與未驗證範圍。
- [ ] 在 CONTRIBUTING.md 加入交付時更新紀錄的導航，明確區分原型與正式完成。
- [ ] 核對每列證據與實際提交、CI、部署紀錄。

## Task 2：正式部署保護

- [ ] 先加入會失敗的測試，涵蓋 CI 提交不符、未通過、任務快照與恢復、重跑或中斷、線上資產不符。
- [ ] 將暫存腳本功能整合進正式部署工具，保留現有映像及 NAS 檢查，保護快照存取權限，不輸出秘密。
- [ ] 支援重跑恢復，僅恢復本次部署暫停的任務；失敗保留快照及可執行的恢復入口。
- [ ] 執行部署測試，更新既有部署文件。

## Task 3：完整手機介面驗收

- [ ] 加入載入完整正式頁面及真實腳本的瀏覽器檢查，實際開啟瀏覽選取與佇列新增介面。
- [ ] 驗證人像載入、固定位置、手機隱藏舊控制、桌面保留舊控制，以及基本關閉與狀態同步。
- [ ] 接入正式容器 smoke 入口，使 CI 與部署都必跑；保留快速 fixture 測試。
- [ ] 執行正式映像驗收，確認失敗會傳遞。

## 完成條件

受影響測試、正式映像及相同提交 CI 通過；交付紀錄分別列出工具已實作與實際生產驗證狀態。這次工具改善不以重啟使用者的服務作為測試手段；生產驗證先使用唯讀資產與介面檢查，下一次部署使用正式工具。
