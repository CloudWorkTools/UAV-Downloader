# ADR-0002: 四個字幕階段皆可獨立使用外部 API

| | |
| --- | --- |
| Status | Accepted |
| Date | 2026-10-20 |
| Deciders | 本次功能規劃的需求提出者、Codex |

本文件記錄已確認的設計決策，功能尚未實作。

## Context

影匣部署主機的資源有限，需求提出者習慣透過 LocalAI 管理模型，也希望使用 Ollama 或 LM Studio。
字幕流程需要獨立選擇各階段服務與模型，模型主機的硬體與版本尚未確定。

## Decision

語音活動偵測、語音辨識、原文後矯正與字幕翻譯四個階段皆須支援外部 API。
使用者可分別設定各階段的服務位址與模型，流程不得要求在影匣主機執行模型。
LocalAI 是預設服務選項，不固定實際位址、硬體或模型大小。

影匣按階段與服務的能力驗證設定，可使用通用相容 API 或服務專用 HTTP API。
服務專用 API 同樣可以呼叫遠端服務，不表示在影匣主機執行模型。
影匣不能將「OpenAI 相容」視為所有階段皆可用的保證。

首版 ASR 必須回傳片段起訖時間與文字，不另外執行強制對齊。
後矯正與翻譯要求停用額外思考模式時，影匣須使用服務與模型支援的控制方式。
無法確認停用時，系統明確告知，預設阻止該要求下的執行，由使用者改選模型或明確允許思考。
失敗時不得自行更換模型、服務或改成本機模型。

## Consequences

Positive: 模型運算可以放在獨立主機，各階段可選擇不同服務。

Negative: 影匣須維護不同 API 的請求與回應處理，並驗證部署版本、模型與後端能力。
外部服務中斷時，該階段必須等待重試或使用者重新選擇設定。

Neutral: 影匣仍負責檔案存取、音訊前處理、分段與時間軸還原。

## Alternatives considered

只支援一種 OpenAI 相容介面：串接實作較少，但無法涵蓋獨立 VAD 與各服務的思考控制差異。

強制在影匣主機執行 VAD：較少依賴外部服務，但會限制部署資源與模型管理方式，不符合需求提出者的設定彈性要求。
